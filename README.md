# Reproducible Research: Data Quality & Analysis (R)

A complete, **standalone R project** that demonstrates a reproducible
data-quality and statistical-analysis workflow on a **synthetic** dataset of
hypothetical sleep patterns and self-reported wellbeing.

> ⚠️ **All data in this project is SYNTHETIC / fictional.** It is generated by
> `R/generate_data.R` purely to demonstrate the workflow and does **not**
> describe real people. No real participants, institutions, supervisors or
> publications are involved, and no empirical claims about sleep or wellbeing
> are made.

The analysis is performed by **real R code** (tidyverse, janitor, ggplot2) and
reported with **R Markdown**. There is no hidden Python/JS layer faking the
statistics — everything runs through `Rscript`.

---

## What it does

1. **Imports** a synthetic CSV of sleep & wellbeing data.
2. **Validates** it: data types, missing values, duplicates, inconsistent
   category labels and invalid/impossible entries.
3. **Cleans** it with transparent, documented functions that **preserve the
   original dataset** (cleaning always operates on a copy).
4. **Analyses** it: descriptive statistics, frequency tables (`janitor::tabyl`)
   and Pearson correlations with hypothesis tests.
5. **Visualises** it with publication-style `ggplot2` figures.
6. **Reports** everything reproducibly in `report/report.Rmd`.
7. **Tests** the core functions with `testthat` using tiny datasets whose
   expected results are known.

## Optional web interface (really runs R)

A small web console is included that **actually invokes the R workflow** — it is
*not* a mock. The FastAPI backend (`backend/server.py`) shells out to `Rscript`
and the React dashboard renders the genuine R outputs (validation metrics,
tables, correlation matrix and the ggplot2 PNG figures).

Key endpoints (all prefixed `/api`):

| Endpoint | What it does |
|----------|--------------|
| `GET /api/health` | reports R version & that packages are installed |
| `POST /api/analysis/run` | runs `scripts/run_analysis.R` via `Rscript` |
| `GET /api/analysis/correlations?method=pearson\|spearman\|kendall` | recomputes correlations in R for the chosen method |
| `GET /api/analysis/subset?gender=…&sleep_quality=…` | re-runs descriptive stats + correlations in R on a filtered subset |
| `GET /api/analysis/anova?factor=sleep_quality\|gender\|mood` | one-way ANOVA of wellbeing across a factor, computed in R |
| `GET /api/analysis/results` | returns the generated R tables as JSON |
| `POST /api/tests/run` | runs the `testthat` suite via `Rscript` |
| `GET /api/analysis/figures/{key}` | serves a ggplot2 PNG produced by R |
| `GET /api/dataset/download?which=raw\|clean` | downloads the CSV |
| `GET /api/report` | serves the rendered R Markdown report |

The web interface is **optional** — the R project is fully usable on its own via
the commands above. The dashboard simply triggers and visualises that same real
pipeline.

## Requirements

* **R >= 4.1** (developed/tested on R 4.2)
* **pandoc** (only needed to render the R Markdown report; bundled with RStudio)
* R packages: `tidyverse`, `janitor`, `testthat`, `rmarkdown`, `knitr`
  (see `requirements-R.txt`)

---

## Setup & run (locally)

```bash
# 0. Install R (e.g. from https://cran.r-project.org) and, optionally, pandoc.

# 1. Install R package dependencies
Rscript setup/install.R

# 2. Generate the synthetic raw dataset  ->  data/raw/sleep_wellbeing_raw.csv
Rscript scripts/make_dataset.R

# 3. Run the full analysis pipeline  ->  outputs/figures + outputs/tables
Rscript scripts/run_analysis.R

# 4. Run the automated tests
Rscript scripts/run_tests.R

# 5. Render the reproducible report  ->  report/report.html
Rscript -e 'rmarkdown::render("report/report.Rmd")'
```

All scripts can be run from the project root (they also auto-correct if run
from inside `scripts/`).

### Using RStudio instead

Open the folder as a project, then `source("scripts/make_dataset.R")`,
`source("scripts/run_analysis.R")`, and knit `report/report.Rmd` with the
**Knit** button.

## Reproducibility

* The synthetic data is generated with a fixed seed (`set.seed(42)`), so every
  run produces the same dataset and the same results.
* The report embeds `sessionInfo()` so the exact package versions used to
  produce it are recorded.
* Cleaning rules (valid ranges, label mappings) are explicit and documented in
  `R/clean.R` and `data_dictionary.md`.

---

## Testing

`Rscript scripts/run_tests.R` runs the `testthat` suite. Examples of checks:

* sentinel strings (`""`, `"NA"`, `"N/A"`) are converted to `NA`;
* `"3 cups"`/`"two"` are coerced to `3`/`NA`;
* impossible values (`age = 200`, `sleep_hours = 30`) become `NA`;
* exact duplicate rows are removed **and the original data frame is unchanged**;
* `mean`/`median`, correlations and frequency counts match hand-computed values.
